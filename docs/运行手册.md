# 运行手册

## 1. 部署拓扑

```text
Internet
  └─ Nginx (TLS, /helpdesk/ -> 127.0.0.1:8091)
       └─ Docker Compose: app (Spring Boot 8091)
            ├─ postgres (pgvector, 不暴露公网)
            └─ redis (不暴露公网)
```

- 服务器：`ubuntu@124.223.36.154`
- 目录：`/opt/helpdesk`
- 公网入口：`https://whereri.site/helpdesk/`
- 应用 jar：`/opt/helpdesk/app/helpdesk.jar`
- 附件目录：`/opt/helpdesk/data/attachments`
- 日志目录：`/opt/helpdesk/logs`
- 备份目录：`/opt/helpdesk/backups`

## 2. 日常检查

```bash
cd /opt/helpdesk
sudo docker compose ps
curl -fsS http://127.0.0.1:8091/actuator/health
curl -fsS http://127.0.0.1:8091/actuator/prometheus | head
sudo docker compose logs app --tail 100
```

重点指标：

- `helpdesk_ai_stream_total{result="error"}`：AI 流式失败率
- `helpdesk_llm_fallback_total`：LLM 降级次数
- `helpdesk_sla_breaches_total`：SLA 超时工单数
- `helpdesk_outbox_pending` / `helpdesk_outbox_failed`：索引事件积压
- `helpdesk_pii_redacted_total`：PII 脱敏次数

平台管理员还可以查看：

```text
GET /api/admin/outbox/status
GET /api/admin/index/status
GET /api/tickets/breached
```

## 3. 发布与回滚

### 发布

```powershell
mvn clean package
scp target\helpdesk-0.1.0.jar ubuntu@124.223.36.154:/opt/helpdesk/app/helpdesk.jar
ssh ubuntu@124.223.36.154 "cd /opt/helpdesk && sudo docker compose up -d --build"
```

发布后必须检查：

1. `/actuator/health` 为 `UP`；
2. `/helpdesk/` 返回 200，静态资源 `/helpdesk/assets/*` 返回 200；
3. 登录、工单列表、客户门户各走一次；
4. 确认 Flyway 版本与代码一致。

也可以在 GitHub Actions 手动触发 `deploy` workflow（需要仓库 secrets：
`SSH_HOST`、`SSH_USER`、`SSH_KEY`），它会构建 jar、上传并重启 Compose。

### 回滚

保留上一个 jar（例如 `app/helpdesk.jar.bak`），回滚时覆盖 jar 后重新
`docker compose up -d --build`。数据库迁移默认只向前；如果本次包含破坏性迁移，
回滚前先用备份恢复到临时库验证，再决定是否回滚数据库。

## 4. 常见故障

### 4.1 公网 502

1. `sudo docker compose ps` 看 app 是否 `Up`；
2. `curl http://127.0.0.1:8091/actuator/health`；
3. `sudo docker compose logs app --tail 200`；
4. `sudo nginx -t && sudo systemctl status nginx`；
5. 如果 app 正在启动，等待 10–15 秒后重试。

### 4.2 AI 不可用

应用会自动重试一次，仍失败时返回固定降级话术并记录
`helpdesk_llm_failed` / `helpdesk_llm_fallback_total`。

排查顺序：

1. `.env` 中 `HELPDESK_LLM_API_KEY` 是否存在；
2. DeepSeek 账户余额和网络连通性；
3. `docker compose logs app | grep helpdesk_llm`；
4. 必要时把租户 AI 开关关闭，走人工客服。

### 4.3 Redis 不可用

登录限流、JWT 撤销、公共门户限流和 outbox 消费会降级或暂停。应用不会因为
Redis 短时不可用而整体崩溃，但会记录日志。

```bash
sudo docker compose restart redis
curl -fsS http://127.0.0.1:8091/actuator/health
```

### 4.4 索引积压 / DLQ

```text
GET /api/admin/outbox/status
GET /api/admin/index/status
```

如果 `pending` 持续增长，检查 `WikiIndexStreamConsumer` 日志和 Redis Stream；
`failed` 事件需要人工确认后重放或丢弃。页面保存本身不依赖索引完成。

### 4.5 附件 404

1. 确认 `docker compose` 的 `./data:/app/data` 挂载存在；
2. 检查 `/opt/helpdesk/data/attachments` 权限；
3. 确认数据库 `ticket_attachment.storage_key` 与磁盘文件一致；
4. 客户只能下载 `PUBLIC` 附件，内部附件返回 404 是预期行为。

### 4.6 磁盘 / 内存

```bash
df -h /opt
free -m
sudo docker stats --no-stream
```

应用 `-Xmx768m`。当前 4C4G 服务器同时跑 PostgreSQL、Redis 和 app，
不建议默认开启 Prometheus/Grafana；需要时用 `--profile observability`。

### 4.7 Wiki 页面检索不到

页面状态必须是 `PUBLISHED` 才会进入检索。新建和编辑保存后是 `DRAFT`，
需要在知识库页点击“提交审核”，再由租户管理员点击“通过”。

```text
GET  /api/wiki/pages/{id}/versions
POST /api/wiki/pages/{id}/submit
POST /api/wiki/pages/{id}/approve
POST /api/wiki/pages/{id}/reject
```

如果状态已是 `PUBLISHED` 仍检索不到，检查 outbox 是否积压、页面是否已重建索引。

### 4.8 租户回收站

- `DELETE /api/platform/tenants/{id}?confirm={slug}`：软删除，进入回收站；
- `POST /api/platform/tenants/{id}/restore`：恢复；
- `DELETE /api/platform/tenants/{id}/purge?confirm={slug}`：立即彻底删除；
- `TenantPurgeScheduler` 每天 03:30 清理超过 30 天的回收站租户；
- 非 `ACTIVE` 租户的已有 token 会被 `TenantFilter` 拒绝；
- 彻底删除时会调用 `AttachmentService.deleteTenantFiles` 清理 `data/attachments/{tenantId}`。

### 4.9 通知铃铛没有未读

```text
GET  /api/notifications/unread-count
GET  /api/notifications?limit=20
POST /api/notifications/{id}/read
POST /api/notifications/read-all
```

通知只在“提交审核”和“通过/驳回”时生成；提交人不会收到自己触发的通知。
如果铃铛没有更新，先确认当前账号是租户管理员或页面负责人，再检查后端日志。

### 4.10 平台审计查询

```text
GET /api/platform/audit?action=tenant.create&targetType=tenant&limit=100
```

前端“平台管理”页底部有审计表格，可按动作和目标类型过滤。审计记录不随租户删除而消失。

## 6. 安全基线

- `.env` 权限保持 `600`，不要提交到 Git；
- JWT secret、DeepSeek key 定期轮换；
- 公网只暴露 Nginx 443/80，PostgreSQL/Redis 只走 Compose 内网；
- 登录限流、JWT `jti` 撤销、安全响应头已启用；
- 客户门户使用 channel key + 查询码，不创建客户账号；
- 附件路径做 normalize + startsWith 校验，文件名清洗。

## 7. 已知限制

- 单机部署，没有多副本和自动故障转移；
- 没有 CDN，静态资源首次加载约 1.4MB；内网/办公网可接受；
- 3M 公网带宽不适合大文件或视频，当前只服务文本工单和附件；
- Prometheus/Grafana 配置已提供但默认不启动；
- CD 目前是手动发布，CI 只负责测试和构建产物。
