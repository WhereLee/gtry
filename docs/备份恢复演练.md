# 备份恢复演练

## 1. 演练结论

- 时间：2026-11-07 15:52（Asia/Shanghai）
- 环境：`/opt/helpdesk`，Docker Compose，PostgreSQL 17 + pgvector
- 备份文件：`backups/helpdesk-20261107-155225.dump`，约 **26MB**
- 恢复目标库：`helpdesk_restore_check`
- 恢复耗时：约 **7 秒**
- 校验结果：`tenant=3`、`ticket=1`、`wiki_page=2500`、Flyway rank/version=`11`
- 结论：备份可用，恢复流程可执行；当前 RTO 约 10 分钟（含应用重启和人工确认）

## 2. 备份命令

```bash
cd /opt/helpdesk
mkdir -p backups
ts=$(date +%Y%m%d-%H%M%S)
sudo docker compose exec -T postgres \
  pg_dump -U postgres -d helpdesk --format=custom --no-owner --no-privileges \
  > backups/helpdesk-$ts.dump
```

附件不在数据库中，必须单独打包：

```bash
tar czf backups/attachments-$ts.tar.gz -C /opt/helpdesk data/attachments
```

## 3. 恢复演练命令

```bash
cd /opt/helpdesk
BACKUP=backups/helpdesk-20261107-155225.dump

sudo docker compose exec -T postgres dropdb -U postgres --if-exists helpdesk_restore_check
sudo docker compose exec -T postgres createdb -U postgres helpdesk_restore_check
sudo docker compose exec -T postgres pg_restore -U postgres \
  -d helpdesk_restore_check --no-owner --no-privileges < "$BACKUP"

sudo docker compose exec -T postgres psql -U postgres -d helpdesk_restore_check -tAc \
  "select (select count(*) from tenant) as tenants,
          (select count(*) from ticket) as tickets,
          (select count(*) from wiki_page) as pages,
          (select max(installed_rank) from flyway_schema_history) as flyway_rank,
          (select max(version::int) from flyway_schema_history) as flyway_version"

sudo docker compose exec -T postgres dropdb -U postgres helpdesk_restore_check
```

仓库中的 `tools/backup-drill.sh` 封装了上述步骤，可在服务器上执行：

```bash
bash /tmp/backup-drill.sh /opt/helpdesk/backups/helpdesk-20261107-155225.dump
```

## 4. 真实恢复流程

如果 `helpdesk` 主库损坏：

1. 停止 app：`sudo docker compose stop app`；
2. 备份当前损坏库（可选）：`pg_dump` 或直接保留 volume；
3. 删除并重建 `helpdesk` 库；
4. `pg_restore` 最新 dump；
5. 恢复附件目录到 `/opt/helpdesk/data/attachments`；
6. 启动 app：`sudo docker compose up -d`；
7. 检查 health、登录、工单、知识库检索和附件下载。

## 5. 建议的备份策略

- 每天 02:30 全量 `pg_dump` + 附件 tar；
- 保留 14 天；
- 每周把最新备份复制到另一台机器或对象存储；
- 每季度做一次恢复演练，记录耗时和校验结果；
- 备份文件加密，访问权限限制为运维账号。

## 6. 注意事项

- `pg_dump` 是逻辑备份，恢复后需要确认 Flyway 版本与当前代码兼容；
- 备份期间应用仍可写入，dump 是一致性快照，但附件目录需要单独处理；
- 备份会包含回收站中的 `DELETED` 租户；恢复后它们仍在回收站，30 天后由调度器清理；
- 不要把 `.env`、JWT secret、DeepSeek key 写入备份文档或仓库；
- 恢复演练使用独立临时库，不要直接覆盖生产库。
