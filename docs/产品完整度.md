# 产品完整度（P2）

P1 解决“回答可信不可信”，P2 解决“小公司拿到系统能不能真的用起来”。本阶段不引入支付、微服务或第二套向量库。

## 1. 工单分诊

创建工单时同步执行规则分诊，结果写入 `ticket.category`、`ticket.priority`、`assignee_id`、`triage_source`、`triage_reason`。

### 分类

规则按关键词打分，标题命中权重 2、正文命中权重 1，取最高分；没有命中进入 `OTHER`。

```text
RETURNS     退货、退款、换货、售后、维修
SHIPPING    物流、快递、发货、配送、地址、签收、运费
INVOICE     发票、抬头、税号、开票、冲红
PAYMENT     支付、扣款、付款、分期、银行卡
ACCOUNT     登录、密码、账号、验证码、找回
MEMBER      会员、积分、等级、优惠券、权益
PRODUCT     商品、规格、兼容、保修、说明书
PROMOTION   活动、满减、拼团、秒杀、价保
COMPLAINT   投诉、赔偿、态度、主管
QUOTA       配额、限制、存储、成员数、超限
BILLING     套餐、计费、续费、账单、订阅
PERMISSIONS 权限、角色、Owner、Admin、Guest、SSO
INTEGRATION 集成、Webhook、API Key、对接
SECURITY    2FA、审计、白名单、安全、风控
BACKUP      备份、恢复、容灾
UPGRADE     升级、降级、套餐变更
EXPORT      导出、下载
DELETION    删除、清理、注销
PRIVACY     隐私、个人信息、授权
SUPPORT     工单、客服、SLA、响应
OTHER       默认
```

### 优先级

| 级别 | 触发 |
|---|---|
| `URGENT` | 投诉、赔偿、欺诈、盗刷、泄露、无法登录、数据丢失、重复扣款、退款失败 |
| `HIGH` | 退款、退货、发票、超时、异常、失败、损坏、少件、丢件 |
| `LOW` | 咨询、建议、如何使用、了解、价格 |
| `NORMAL` | 其他 |

`COMPLAINT`、`PRIVACY`、`SECURITY`、`PAYMENT` 即使没有命中高风险词，也至少是 `HIGH`。

### 路由

按当前租户内 `AGENT` 优先、未关闭工单数最少、用户 ID 排序，选择负责人；没有可用坐席时保持未分配。

### 人工调整

```text
POST  /api/tickets/{id}/triage    重新跑规则
PATCH /api/tickets/{id}/triage    人工调整 category / priority / assigneeId
```

人工调整会把 `triage_source` 记为 `MANUAL`，便于和规则分诊区分。

## 2. 客服人工回复

工单详情页提供回复框，调用 `POST /api/tickets/{id}/messages`。

- 坐席回复后，`OPEN` / `CLOSED` 工单自动转为 `PENDING`；
- 消息以 `AGENT` 类型落库，与 `CUSTOMER`、`AI` 消息区分；
- `Ctrl+Enter` 可直接发送。

## 3. 用量面板

```text
GET /api/usage/summary          本月 tokens、预算、成本、限流
GET /api/usage/daily?days=14    按自然日聚合，缺失日期补 0
```

前端“用量”页展示本月 tokens、预算使用率、成本、限流和近 14 天柱状图。平台管理页的租户表同时展示每个租户的本月 tokens / 预算。

## 4. 平台租户管理

平台管理员登录后可见“平台”页。

### 开通

`POST /api/platform/tenants` 在一个事务内完成：

1. 创建 `tenant`；
2. 创建 `TENANT_ADMIN` 用户；
3. 创建默认知识空间 `default`；
4. 写平台审计。

### 停用/启用

`PATCH /api/platform/tenants/{id}/status?status=ACTIVE|SUSPENDED`。

`AuthService` 在登录时检查租户状态，停用租户返回 `tenant_inactive`，已有 token 仍受 RLS 约束。平台租户不能停用或删除。

### 导出

`GET /api/platform/tenants/{id}/export` 返回 JSON，包含：

- 租户信息；
- 用户（不含密码哈希）；
- 工单与消息；
- wiki 空间、页面、小节；
- 用量事件；
- 审计日志。

导出会写平台审计 `tenant.export`。

### 删除

`DELETE /api/platform/tenants/{id}?confirm={slug}`。

- 必须输入租户 slug 确认；
- 租户状态先置为 `DELETING`，异步级联删除；
- `GET /api/platform/tenants/{id}/delete-status` 查询任务状态；
- `platform_audit_log` 不引用 `tenant(id)`，所以租户删除后审计仍保留；
- 删除失败会把租户恢复为 `ACTIVE`，任务状态为 `FAILED`。

## 5. 数据库与审计

V4 迁移新增：

- `ticket.category`、`ticket.triage_source`、`ticket.triage_reason`；
- `ticket(tenant_id, category, created_at desc)` 索引；
- `platform_audit_log`（平台级，不随租户级联删除）。

## 6. 暂未实现

### wiki 版本历史/审批

没有做。原因：

- 需要 `wiki_page_version`、版本对比、回滚、审批状态和通知，工作量约 2–3 天；
- 当前知识库编辑已经写 `audit_log`，能追溯“谁在什么时候改了什么页面”，但不保存正文快照；
- 对 10–100 人公司，先用审计日志 + 页面负责人 + 过期报告更划算。

后续做法：

1. 新增 `wiki_page_version(id, tenant_id, page_id, version, title, visibility, sections jsonb, created_by, created_at)`；
2. 每次更新前写一条版本快照；
3. 增加 `GET /api/wiki/pages/{id}/versions`、`POST /api/wiki/pages/{id}/rollback/{version}`；
4. 审批流增加 `DRAFT/REVIEW/APPROVED` 状态和租户管理员审批端点；
5. 前端增加版本列表和 diff 视图。

### 其他边界

- 分诊是规则引擎，不是 LLM 分类；这样不依赖外部模型，延迟稳定，也便于解释。需要 LLM 时可以把 `TicketTriageService` 作为兜底，在前面加一层模型分类。
- 租户删除是级联硬删除，没有 30 天回收站；如果要做，先软删除 + 定时清理。
- 平台审计目前只入库，没有平台审计查询页；数据已经在，后续加一个只读接口即可。
