# 异步索引

页面保存不再同步等待 embedding。链路如下：

```text
WikiPageService 事务
  ├─ 写 wiki_page / wiki_section
  └─ 写 outbox_event(WIKI_PAGE_INDEX)
        ↓  OutboxPublisher 每 2s 轮询
  Redis Stream: helpdesk:stream:index
        ↓  WikiIndexStreamConsumer 消费组 helpdesk-index
  WikiIndexService.indexPage
        ↓
  wiki_chunk（向量 + tsvector）
```

## 可靠性

- **事务性 outbox**：页面和事件在同一个数据库事务里，业务成功事件一定存在；
- **发布重试**：发布失败按 2/4/8/16/32 秒退避，最多 5 次，之后 `FAILED`；
- **PEL 重投**：消费者失败不 ACK，消息留在 Pending Entries List；
  每轮用 `XCLAIM` 认领 idle ≥ 60 秒的消息；
- **DLQ**：同一消息失败 5 次后写入 `helpdesk:stream:index:dlq` 并 ACK 原消息；
- **幂等**：索引按 section upsert，重复消费不会产生重复 chunk；
- **卡住恢复**：`PUBLISHING` 超过 30 秒会被重置为 `PENDING`。

## 观测

```text
GET /api/admin/index/status    pages/sections/chunks/questions + pending/failed 索引事件
GET /api/admin/outbox/status   pending/publishing/published/failed/dlq
```

日志：

```text
helpdesk_outbox_published
helpdesk_outbox_publish_failed
helpdesk_index_retry
helpdesk_index_dlq
helpdesk_index_stream_poll_failed
```

## 当前边界

- 种子数据仍用同步批量索引，避免 1 万小节时产生 1 万条 outbox；
- DLQ 只保留消息，没有自动重放页面；排查后可以手动重投或重新保存页面；
- 单机消费者组足够当前规模；多实例部署时每个实例用不同 consumer name。
